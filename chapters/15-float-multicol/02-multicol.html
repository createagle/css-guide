Multi-column layout pours one flow of content into columns, like a newspaper. You do not decide which paragraph goes into which column: the browser balances the content so the columns end at about the same height.

Give it a column width rather than a column count, and the number of columns follows the width of the container. A wide screen gets three or four columns, a phone gets one, and no media query is needed.

Boxes such as this note can be split across two columns. break-inside: avoid keeps each one in one piece.

Columns work best for short items that can be read in any order, such as lists of links, tags or footnotes. For long articles on a screen, the reader has to scroll down, back up, and down again.

Spanning heading

A heading with column-span: all cuts across every column. The content before it is balanced into one set of columns, and the content after it starts a new set below.

Column rules are drawn in the middle of each gap. They take no space, so they never change the width of a column, much like an outline.

A second note, also kept in one piece when break-inside is set.

If the container has a fixed height, columns that do not fit overflow sideways instead of growing downwards. That is almost never what you want on a web page, so let the height follow the content.
